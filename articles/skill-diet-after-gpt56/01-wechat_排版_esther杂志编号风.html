1）Codex：让它自己清 Skill

PROMPT · CODEX SKILL

扫描 ~/.codex/skills（含软链/镜像），结合最近 session 日志：


1) 列出：30 天内未使用 / 功能重复 / 只做发现与安装的 skill

2) 建议：保留 / 隔离 / 删除，每条写清理由与替代项

3) 经我确认后，把建议移除的移到 ~/.codex/skills/_quarantine/

4) 不要碰 .system 里的官方 skill，除非我点名

5) 限制 find-skills：只发现，不自动 install


先给 diff 计划，我确认后再执行。

2）Codex：按日志维护 Skill

PROMPT · LOG DRIVEN

scan my local codex session logs, look for common failure patterns,

then find, create, install, remove and/or modify skills to address those patterns.


Show a plan and file diffs first. Do not apply until I approve.

3）Claude Code：跑原生体检

PROMPT · CLAUDE /DOCTOR

运行 /doctor（或 /checkup）。

重点：unused skills、MCP、plugins 冗余；CLAUDE.md 去重；能省 context 的项列清单。

先报告，再按我的确认清理。

记住一句

Claude 的 cleanup 在命令里；Codex 的 cleanup 在你的 Prompt 里。
两边都先看报告，确认后再动文件。

Why
二、为什么 5.6 之后更该清
━━━━

社区有一句几乎成了口令：

GPT-5.5：加 skill

GPT-5.6：删 skill

不是段子。高强度用完 Sol 之后，很多人第一件事就是 gut skills：砍掉野心过大的流程 Skill，把 AGENTS.md 删掉大半。 约束一多，模型开始被说明书牵着走；流程太重，强模型会「勤快地跑偏」。

最贵的 Token，经常花在 错误交付物上的正确劳动 上：每一步都做得很认真，交出来的却不是你要的东西。

━━━•
Compare
三、Claude Code 的 cleanup，Codex 怎么办
━━━━

入口

Claude Code · /doctor、/checkup

Codex · 没有对等原生体检命令

做什么

Claude · 诊断配置、清 unused skills/MCP/plugins、配置去重、省 context

Codex · 你让它扫 ~/.codex/skills + 日志，自己增删改

体验

Claude · 菜单/命令稳定

Codex · 灵活：可按失败模式改 skill 库存

你要补的

Claude · 定期跑

Codex · 把「清理 Prompt」当成常驻运维

推上有开发者说得很直白：Claude 有 /doctor，Codex 没有原生版。有人补 cleanup skill，更多人直接用自定义提示词让 Codex 自己维护。

对多数人来说，这已经够用。Codex 本来就能读写本地 skill 目录，缺的是一份明确的维护要求。

另外两条容易踩坑：

01

Skill 一多，Codex 会变慢。有人减到十来个，速度明显回来。

02

find-skills 会按需下载。清理时要么拿掉，要么限制成「只发现、不自动装」。

Takes
四、推上反复出现的五个判断
━━━━

1. 模型变强，旧约束要重新审视

5.6 之后清理旧 skill，有些 skill 反而拖慢模型

AGENTS.md 删大半：约束过多成干扰

去掉 superpowers 一类「过于野心」的流程 skill

甚至有人删光 skill，用 Sol 带 Terra / Luna 分层打杂

把多余的减掉，再调剩下的；别用更多 skill 解决 skill 太多。

2. 给库存设一道硬门槛

Skills 过多 → 变慢；减到少量常用后更快

发现通道与安装通道分离，防止越清越装

核心库设个上限，剩下的先放隔离区。发现和安装也要拆开。

3. 维护依据来自 session 日志

一套常见的提示结构是：

扫 session 日志 → 找常见失败模式 → find / create / install / remove / modify skills

隔一段时间跑一次就够了。日志会告诉你哪些规则真的救过场。

4. 编排薄一点，模型才能把力气用对地方

默认单 Agent、Skill 按需

开 Skill 前只问：会不会改变当前任务的做法？

AGENTS.md 只留「防反复错误」的红线，口号删掉

想省 Token，把任务边界说清楚通常比抠参数更有用。

5. 安装时就该考虑以后怎么删

让模型去 GitHub 找 skill ≠ 原样全装

license → pin commit → 查依赖权限 → 只留贴合自己的 → 再测

More Skills ≠ better agent。
