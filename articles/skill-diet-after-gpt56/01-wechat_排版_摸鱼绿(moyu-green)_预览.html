真正拉开差距的，是你敢不敢做减法

很多人把 GPT-5.6 当成「更强的续杯」。真正拉开差距的，往往是另一件事：你敢不敢做减法。

下面这篇不推第三方清理工具。先给你能直接粘贴的维护指令，再讲 Claude Code 与 Codex 怎么清，以及推上反复出现的高赞观点。

PART

为什么 5.6 之后更该清

WHY · LESS IS MORE

社区有一句几乎成了口令：

GPT-5.5：加 skill
GPT-5.6：删 skill

不是段子。高强度用完 Sol 之后，很多人第一件事是 gut skills——砍掉野心过大的流程 Skill，把 AGENTS.md 删掉大半。因为约束太多，开始干扰模型；流程太重，强模型会「勤快地跑偏」。

最贵的 Token，经常不是偷懒花掉的，而是花在 错误交付物上的正确劳动 上：每一步都很认真，交出来的却不是你要的东西。

PART

Claude Code 的 cleanup vs Codex 的自定义提示词

COMPARE · TWO PATHS

维度Claude CodeCodex
入口/doctor、/checkup没有对等原生体检命令
做什么诊断配置、清 unused skills／MCP／plugins、配置去重、省 context扫 ~/.codex/skills 与日志，自己增删改
体验菜单／命令稳定灵活：可按失败模式改 skill 库存
你要补的定期跑把「清理 Prompt」当成常驻运维

推上有开发者写得很直白：Claude 有 /doctor，Codex 没有原生版，所以要么社区补 cleanup skill，要么——更常见——直接用自定义提示词让 Codex 自己干。

对多数人，第二种就够用：Codex 本来就能读写本地 skill 目录，缺的不是能力，是你有没有把 维护话说清楚。

另外两条容易踩坑

1

Skill 一多，Codex 会变慢。有人减到十来个，速度明显回来。

2

find-skills 会按需下载。清理时要么拿掉，要么限制成「只发现、不自动装」。

04

PART

推上高赞／高频的观点与建议

SIGNALS · PRACTICES

1．模型变强，默认做减法

清理旧 skill

5.6 之后清理旧 skill，有些 skill 反而拖慢模型。

约束瘦身

AGENTS.md 删大半：约束过多成干扰。

流程降级

去掉 superpowers 一类「过于野心」的流程 skill。

分层打杂

甚至有人删光 skill，用 Sol 带 Terra／Luna 分层打杂。

建议：先减再调；不要用更多 skill 解决 skill 过多。

2．给库存设上限

Skills 过多会变慢；减到少量常用后更快。把 发现通道与安装通道分离，防止越清越装。

建议：个人库设硬顶（例如核心十来个），其余一律隔离区。

3．让 Agent 自己维护 Skill

高互动提示结构是：

扫 session 日志 → 找常见失败模式 → find／create／install／remove／modify skills
经常跑，agent 会随时间变好。

建议：清理是日志驱动的小循环，不是年底大扫除。

4．编排变薄，模型变厚

默认单 Agent

Skill 按需开启。

开 Skill 前只问

会不会改变当前任务的做法？

只留红线

AGENTS.md 只留「防反复错误」的红线，口号删掉。

建议：省 Token 先管任务边界，再管参数表。

5．安装纪律也是清理

让模型去 GitHub 找 skill，不等于原样全装。正确顺序是：license → pin commit → 查依赖权限 → 只留贴合自己的 → 再测。

建议：More Skills ≠ better agent。
