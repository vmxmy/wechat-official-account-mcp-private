跨生态：猫头鹰当脑子，罗威纳做牛马

左 Fable 当脑子，右 Sol 做牛马

日推里最好记的说法是：

  • Fable ≈ 猫头鹰：看得深，会问「该不该做」
  • Sol ≈ 罗威纳：咬住任务，默默干到结束

脑子 → Fable。牛马 → Sol。分工就这么粗暴。

别自己写超长 prompt。

也别让 Fable 直接改生产代码。

更稳的流程只有三步：

  1. 你说目标、边界、不能做什么
  2. Fable 写成验收、影响范围、测试、风险
  3. 原样丢给 Codex + Sol

中间少一层「人手翻译」，少一次信息损耗。

牛马位，不要自己终审。同一模型会给自己找补。

角色怎么分：

  • 脑子位（Fable）：架构、产品边界、咨询、评审
  • 牛马位（Sol）：跨文件实现、长清单、贴合存量代码

只剩一个名额时，很多人仍选 Fable。

因为脑子位更稀缺，不是因为牛马不重要。

七种几乎被统一的用法

七种几乎被统一的用法

日本圈把上面这套，收敛成七种几乎统一的用法：

  1. Fable 写指示，Sol 去执行——脑子出指令，牛马去落地
  2. 设计归 Fable，实现归 Sol——脑子想清楚，牛马干完
  3. 商量找 Fable，写码找 Sol——脑子位和牛马位别混会话
  4. 有意让 Fable 指挥 Sol——脑子规划 → 牛马执行 → 换模型只读复审
  5. 长文偏 Fable；研究有时选 Sol——别默认最强编程模型=最强写手
  6. 按任务选，不按信仰选——Fable 聪明偶漏；Sol 未必最机灵但会收尾
  7. 日常三步：对稿、重活、手脚——额度、速度、风险的工程选择

最小闭环再写一遍：

  1. 脑子规划
  2. 牛马执行
  3. 换模型只读复审

别在一个窗口里从聊天聊到上线。

脑子当脑子，牛马做牛马——角色一旦反了，账单和事故会一起涨。

Ben 的 GPT-5.6 三档

Ben 的 GPT-5.6 默认搭配

只在 OpenAI 栈里干活时，Ben 的组合很实用：

  1. 主要开发 + 创意 → Sol medium

够强，又没那么烧；常作牛马位默认值

  1. 复杂任务 → 开 Ultra

大量 Subagent 跑后台；子代理可以是 Sol，也可以是 Terra

  1. 日常对话 → Luna xhigh

聊天、轻问轻答，把贵模型省下来

三档体感，也请直接记：

  • Sol：UI 可以，给参考更好；Max 写作强，聊起来有意思
  • Terra：像 GPT-5.5 升级版，更听话，适合当牛马子代理
  • Luna：有点小模型味；提示词糊就 get 不到

任务定义清楚，才不掉链子。不是模型不行，是脑子还没把规格想清楚。

一张作战卡

一张能直接贴团队墙的作战卡

跨生态路由：

  1. 意图糊 → 脑子位上 Fable 对稿
  2. 规格清 → 牛马位上 Sol medium 执行
  3. 终审 → 换模型、只读

纯 OpenAI 路由：

  1. 主开发 / 创意 → Sol medium 当牛马
  2. 复杂可并行 → Ultra + Sol/Terra 子代理
  3. 日常对话 → Luna xhigh

Fable 当脑子写指令，Sol 当牛马去干活。聊天 Luna，复杂 Ultra，Terra 当听话的牛马手。

别踩这些坑

  • 全程 Sol Ultra 吃到饱
  • 模糊需求硬塞 Luna
  • Full Access 加无沙箱
  • 牛马会话自己终审
  • 一个对话从闲聊做到上线

请先只做影响范围和简短规格。写完后停止，等确认。不要直接改代码。

本周就能落地

  1. 双模型规则做成 Skill，别塞进所有聊天
  2. 主开发默认 Sol medium，别一上来 Max / Ultra
  3. 子 Agent 预先钉死模型
  4. 给 Sol 做 UI 时附参考，不要只丢形容词
  5. 看可合并的 diff，不看 tool 调用次数

结语

编排时代，胜负手不是榜单第一。

是你有没有把「想」和「做」拆开，再给「做」配上匹配成本的档位。

Fable 和 Sol 不是信仰之战。

Luna / Terra / Sol 也不是面子工程。

它们是同一条产线上的不同工位。

脑子负责想清楚。牛马负责干完。
