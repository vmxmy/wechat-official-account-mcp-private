Fable当脑子，Sol做牛马？

GPT-5.6 之后，AI 圈吵架的主题变了。

不是「谁吊打谁」，是 Fable 和 Sol，谁当脑子、谁做牛马。

日本开发者圈高收藏帖结论一致，Newsletter 博主 Ben 又补了 OpenAI 三档搭配。这篇把两边捏一起，方便直接抄。

脑子坐哪里？牛马坐哪里？

分工：猫头鹰当脑子，罗威纳做牛马

日推最好记的说法：

  • Fable ≈ 猫头鹰：看得深，问「该不该做」
  • Sol ≈ 罗威纳：咬住任务，干到结束

更稳的流程只有三步：

  1. 你说目标、边界、禁区
  2. Fable 写成验收、影响范围、测试、风险
  3. 原样丢给Codex + Sol

少一层人手翻译，就少一次信息损耗。牛马位别自己终审，同一模型会给自己找补。

只剩一个名额，很多人仍选 Fable。脑子位更稀缺，不是牛马不重要。

脑子当脑子，牛马做牛马。角色反了，账单和事故一起涨。

用法：收敛成一条主线

日本圈收敛出四个原则：

  1. 设计归 Fable，实现归 Sol
  2. 商量找 Fable，写码找 Sol——别混会话
  3. 让 Fable 指挥 Sol：规划 → 执行 → 换模型复审
  4. 按任务选，不按信仰选——Fable 偶漏，Sol 会收尾

最小闭环：脑子规划 → 牛马执行 → 换模型只读复审。别在一个窗口从聊天做到上线。

Ben 的 GPT-5.6 三档

只混 OpenAI 栈，Ben 的组合很实用：

  • 开发 / 创意 → Sol medium：够强又不烧，牛马位默认
  • 复杂任务 → Ultra：后台 Subagent，子代理用 Sol 或 Terra
  • 日常对话 → Luna xhigh：闲聊省额度

体感直接记：Sol 做 UI 要给参考；Max 写作强。Terra 是 GPT-5.5 升级版，更听话，适合当子代理。Luna 提示词糊了容易 get 不到。

任务定义清楚，才不掉链子。

一张作战卡

AI 模型作战卡

跨生态路由

  1. 意图糊 → Fable 对稿
  2. 规格清 → Sol 执行
  3. 终审 → 换模型、只读

纯 OpenAI 路由

  1. 主开发 / 创意 → Sol medium
  2. 复杂可并行 → Ultra + Sol/Terra
  3. 日常对话 → Luna xhigh

Fable 写指令，Sol 去干活。聊天 Luna，复杂 Ultra，Terra 当听话的牛马手。

别踩这些坑

  • Sol Ultra 吃到饱
  • 模糊需求塞 Luna
  • Full Access 无沙箱
  • 牛马自己终审
  • 一聊到底

本周落地

  • 双模型规则做成 Skill
  • 主开发默认 Sol medium
  • 子 Agent 钉死模型
  • Sol 做 UI 附参考
  • 看 diff，不看 tool 次数

安全提示：先做影响范围和简短规格。写完停，等确认。别直接改代码。

结语

编排时代，胜负手不是榜单第一。

是你有没有把「想」和「做」拆开，再给「做」配上匹配成本的档位。

Fable / Sol / Luna / Terra 不是信仰战，是同一条产线上的不同工位。

脑子想清楚。牛马干完。
