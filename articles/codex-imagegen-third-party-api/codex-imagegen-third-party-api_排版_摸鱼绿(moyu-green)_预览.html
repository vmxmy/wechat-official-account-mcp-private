怎么选择

原生还是 API

真正的问题不是支不支持

而是你有没有告诉 Codex 应该走哪条路

你让 Codex 生成一张图片。官方登录时顺利出图；切到第三方 API 后，却提示图片能力不可用。

于是，大多数人的判断是：Codex 把第三方生图封死了。这个判断只对了一半。

被限制的往往只是内置的 hosted 工具；官方 Skill 还准备了完整的 Python CLI 与 Images API 路径，还能控制模型、质量、输出路径和并发。

01

PART


imagegen 不是只有内置生图

ARCHITECTURE · 两条执行路径

打开本地官方 SKILL.md，开头写得很明确：它只有两个顶层模式。

模式执行者适用场景
内置工具image_gen官方订阅、日常单图
CLI／APIimage_gen.py第三方 API、批量并发

CLI 与 API 不是两套互相独立的能力。CLI 是官方封装好的 Python 客户端，底层调用两个标准端点：

...HTTP

POST /v1/images/generations

POST /v1/images/edits

内置解决开箱即用，CLI／API 解决可控、可换、可批量

误判是怎么发生的

MISREAD · 默认入口不等于全部能力

很多人只在 CC Switch 中切换了 Codex 的编程 Provider，然后直接说“生成一张图片”。但官方 Skill 的默认规则是：普通生图请求优先使用内置工具。

如果第三方 Provider 不支持 hosted tool，调用自然失败。这不等于 Python CLI 失败，更不等于 Images API 失败。

03

PART


一次配置，长期指向第三方 API

SETUP · 不修改官方脚本

STEP 01

确认脚本并安装 SDK

...bash

export IMAGE_GEN="$HOME/.codex/skills/.system/imagegen/scripts/image_gen.py"

uv pip install openai

STEP 02

设置标准环境变量

...bash

export OPENAI_BASE_URL="https://你的第三方域名/v1"

export OPENAI_API_KEY="你的 API Key"

脚本内部直接创建 OpenAI() 客户端，SDK 会读取这两个标准变量。所以，不需要增加 --base-url，也不要修改系统 Skill。

STEP 03

写入启动文件，永久生效

macOS／zsh 用户把三行变量写入 ~/.zprofile，再执行 source ~/.zprofile。Bash 用户写入对应启动文件。

真实 Key 不要写进仓库、Prompt、截图或聊天记录。团队环境应通过系统钥匙串或 Secret Manager 注入。

04

PART


让 Codex 永久优先走 CLI

PREFERENCE · 环境与执行偏好分开

环境变量解决“脚本往哪里请求”；AGENTS.md 解决 Codex 默认选哪条路径。

...AGENTS.md

## Image generation preference

- Use the official imagegen Skill's fallback CLI/API mode.

- Read OPENAI_BASE_URL and OPENAI_API_KEY from the environment.

- Prefer gpt-image-2; use generate-batch for distinct assets.

- Never print, persist, or request the full API key.

这段规则就是一次明确的用户偏好，不会与官方 Skill 的默认规则冲突。使用 CC Switch 时，可以把它放进 Prompt／AGENTS.md 管理，再保存为“第三方生图”项目配置。

CC Switch 负责切换与同步配置；真正调用第三方图片接口的，仍然是官方 Python CLI。

06

PART


隐藏能力：五路并发批量生图

BATCH · 多个资产同时生产

官方 CLI 直接提供 generate、edit、generate-batch 三个子命令。其中，批量模式支持异步并发。

先准备 prompts.jsonl

...jsonl

{"prompt":"AI Agent 调研信息源，编辑插画，无文字","out":"01-research.png"}

{"prompt":"AI Agent 拆解计划，编辑插画，无文字","out":"02-plan.png"}

{"prompt":"AI Agent 编写代码，编辑插画，无文字","out":"03-code.png"}

{"prompt":"AI Agent 执行测试，编辑插画，无文字","out":"04-test.png"}

{"prompt":"AI Agent 审查提交，编辑插画，无文字","out":"05-review.png"}

再以五路并发执行

...bash

python "$IMAGE_GEN" generate-batch \

　--input prompts.jsonl --model gpt-image-2 \

　--quality low --size 1024x1024 \

　--out-dir output/imagegen/agent-workflow \

　--concurrency 5 --max-attempts 3 --no-augment

！别混淆两个参数 🕳

--n 5 是同一个 Prompt 的五个变体；generate-batch 是五个不同 Prompt 的五项资产。

真实测试：五项全部成功

BENCHMARK · 理论之外的证据

我们使用某第三方 OpenAI 兼容服务做了真实测试，具体地址已隐去。模型接口返回 67 个模型，并包含 gpt-image-2。

指标结果

测试也发现一个兼容偏差：请求 1024×1024，上游实际返回 1254×1254。这再次证明：能出图不等于每个参数都与官方完全一致。

08

PART


出错时，按表排查

TROUBLESHOOTING · 七个高频问题

现象原因处理
401Key 无效检查并轮换 Key
404只有对话接口换 Images API 入口
有模型不出图端点未实现真实低质量测试
仍走内置未声明偏好写入 AGENTS.md
仍请求官方缺 Base URL注入环境变量
尺寸不一致上游后处理检查并本地缩放
并发 429上游限流降低并发并重试

在 CC Switch 中修改 Codex Provider，不必然等于修改 Python SDK 的 Base URL。前者影响编程模型，后者影响图片请求。

编程走 A，生图走 B，不是缺陷，反而是职责分离

09

PART


哪种模式更适合你

DECISION · 原生与 API 不必二选一

日常单图

内置 image_gen

批量生产

CLI + 第三方 API

混合使用

按任务切路径

如果你有官方订阅，偶尔生成一两张图，内置模式最省事。如果你需要第三方 API、批量资产、固定输出路径或并发任务，CLI／API 模式更合适。

两种能力不必二选一。这才是官方 imagegen Skill 真正完整的用法。

大多数人不是被限制了，只是没看见官方留好的第二扇门

最后强调一次：第三方服务必须真正兼容 /v1/images/generations。只有模型名称，没有接口实现，不算支持。

你现在更愿意用哪种方式？评论区只打两个词之一：原生／API。

参考：OpenAI Codex 官方 imagegen Skill，github.com/openai/codex

LAST


丢给 Agent 解决

ONE PROMPT · 配置、验证、并发一次完成

不想自己查路径、配环境变量、改长期偏好？把下面这段 Prompt 直接发给 Codex、Claude Code 或其他能操作本机文件和终端的 Agent。

执行前，只需要替换第三方接口地址和 API Key。剩下的检查、配置、单图验证与五路并发测试，让 Agent 一次做完。

...PROMPT

请帮我完成 Codex imagegen 第三方 API 的永久配置，并实际验证可用性。

我的配置：

- API Base URL：{{第三方 API Base URL，例如 https://example.com/v1}}

- API Key：{{第三方 API Key}}

- 生图模型：gpt-image-2

- 默认并发数：5

请按以下要求执行：

1. 完整读取本机官方 imagegen Skill 的 SKILL.md，定位 scripts/image_gen.py；不要猜路径，也不要改坏系统 Skill。

2. 检查 Python、uv 和 openai SDK；缺少时只安装必要依赖。

3. 安全、长期配置 OPENAI_BASE_URL 与 OPENAI_API_KEY；不要把明文 Key 写进项目仓库、AGENTS.md、提交记录或终端输出。

4. 在当前项目 AGENTS.md 中只写不含密钥的偏好：生图优先调用 image_gen.py，模型使用 gpt-image-2，批量任务默认允许五路并发。

5. 先验证模型列表或兼容性，再调用 /v1/images/generations 生成一张低质量测试图，保存到 output/imagegen-test。

6. 单图成功后，提交五个不同提示词进行并发测试，并发上限为 5；记录成功／失败、耗时、返回尺寸和文件路径。

7. 失败时根据实际响应定位 401、404、429、模型映射、尺寸偏差或端点不兼容；不要伪造结果。

8. 最后报告修改了哪些配置、密钥保存在哪里、测试证据、以后如何调用、如何撤销；API Key 必须脱敏。

开始前说明发现的 Skill 路径和安全配置方式，然后直接执行；除非要覆盖已有配置或涉及高风险操作，否则不要反复询问。
