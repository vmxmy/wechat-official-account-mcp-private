# 外包给 Agent 的，不该是你的主权

> Agent 越能干，人越容易把手和脑子一起交出去。真正该外包的是执行，不是目标、品味与责任。

最近到处都是同一句话：把任务丢给 Agent。  
能跑代码、能写文案、能拆需求、能连着干几个小时。于是一个幻觉也跟着长出来——

**既然它能干，我是不是可以不用想？**

不能。

Agent 放大的是你的目标，不是替你拥有目标。  
工作没有消失，只是上移了一层：你从键入员，变成了**制片人**。

---

## 先给一张分工总表

| 交给 Agent | 留给自己 |
|------------|----------|
| 重复生产、浅层阅读、低风险执行 | 定方向、定好坏、定禁区 |
| 脚手架、初稿、摘要、对比表 | 品味、品牌声音、关键关系 |
| 可回滚的改动、隔离子任务 | 钱、生产、合规、对外承诺 |
| 按清单调研、格式转换 | 现实反馈与复盘 |
| 多版候选 | 最终签字与责任 |

记住一句就够：

**外包双手，不外包主权。**

---

## 01 什么活，该扔给 Agent

适合 Agent 的，通常同时满足三件事：

1. **结果可验证**（你能很快看出来对不对）  
2. **错误成本低**（错了是麻烦，不是灾难）  
3. **上下文够浅**（不靠你脑子里那本没写下来的公司暗知识）

常见清单：

- 邮件草稿、会议纪要、周报骨架  
- 文章摘要、资料初筛、竞品列表  
- 脚手架代码、API 样板、图表和前端原型  
- 按清单做的结构化调研  
- 可以切开的并行子任务（独立模块、独立复审）

Box 的 Aaron Levie 说得很准：Agent 把工作抬高一层之后，人的活变成——

**下指令、给上下文、纠偏、验收、把输出拼进更大系统。**

任一步掉链子，产物就是废的。  
任务越长，计划和验收越重，不是越轻。

工程圈里 Balaji 有一套好记的启发式：Agent 更像**实习生**。

更适合前端而不是核心后端，更适合读而不是高风险写，更适合浅层而不是内核，更适合原型而不是生产，更适合容错域而不是零容错域。

把它想成同心圆：

- **外圈**（界面、图表、样板、调研）→ 大胆交给 Agent  
- **内核**（业务规则、钱、身份、信任）→ 人主控  

还有一条很现实的边界：  
**写清规格 + 验收 + 切换上下文**，如果已经比自己做还慢，就别硬委派。  
Guillermo Rauch 把这叫委托开销——Agent 再快，也挡不住「说明比动手贵」。

## 02 什么活，必须留给自己

留给自己的，不是「显得你很忙」，而是**只有人能承担的主权**。

### 定方向

做什么、不做什么、为谁做、怎样算成功。  
Agent 很会优化你给的目标；它不会替你选择人生和商业方向。

### 定好坏

产品调性、文风、设计是否高级、品牌能不能碰某类表达。  
这叫**品味**。品味外包之后，你得到的是平均分流畅，不是立场。

### 守高风险写操作

转账、上线、删数据、对客户承诺、法律与合规口径。  
这里需要的是可追责的人，不是流畅的 token。

### 守高上下文核心

核心链路、资金逻辑、权限模型、那些「老员工都懂但文档没有」的约束。  
实习生最容易在这里闯祸——Agent 也一样。

### 闭合现实反馈

真实用户有没有买单，市场有没有打脸，一次亏损说明了什么。  
Agent 内部可以很长：拆解 → 调用 → 自改 → 再输出。  
**内循环变长，不等于更接近现实。**  
现实反馈一少，系统就会在幻觉里非常勤奋。

### 训练自己

读难书、见高人、复盘最痛苦的决策。  
这不是情怀，是维护你自己的底座。

中文互联网里有个很锋利的三分法，值得当长期框架：

| 层 | 是什么 | 态度 |
|----|--------|------|
| **Workflow** | 回邮、填表、写周报——像 Inference 耗材 | 尽量外包 |
| **Skills** | 某门手艺、某个工具的熟练度 | 会贬值，别当唯一护城河 |
| **Base Model** | 世界观、决策框架、审美 | 唯一要加练的东西 |

口号可以压成八个字：

**少 Inference，多 Training。**

别把整个人生的算力，烧在死循环执行上。

## 03 五个决策测试，比鸡汤管用

遇到「要不要丢给 Agent」时，按顺序过一遍。

### 测试一：错误成本

- 错了只是重做 → 倾向 Agent  
- 错了昂贵或不可逆 → 人主导  

### 测试二：能否五分钟验收

能快速看出好坏 → 可外包执行  
说不清什么叫完成 → 先别外包，先写标准  

### 测试三：委托是否更慢

prompt + 验收 > 自己做 → 自己做，或先沉淀模板再外包  

### 测试四：是否碰红线

钱、生产环境、合规、对外承诺 → **默认人工门**  
Agent 可以准备材料，不能替你按发射键  

### 测试五：是否内核

高上下文、暗知识、组织政治 → 人主控  
浅层、可见、可回滚 → Agent 可冲  

组织上还可以用三档：

1. **自己 + AI**：计划清楚、有人负责、能锁时间  
2. **只买搭建**：团队能跑，卡在工具接入与培训  
3. **持续外包**：方向不清、总执行不掉、需要专才  

原则只有一句：**只买能补缺口的最小帮助。**

工程实践里也有同构做法：主 Agent 管需求、范围和**最终验收**；很小的修改自己做；只有需要隔离上下文、并行或独立复审时，才把任务拆出去。

## 04 主体性不是反 AI，是当导演

很多人怕的是「被 AI 取代」。  
更隐蔽的风险是：

**你还在上班，但主体性已经被掏空。**

表现很常见：

- 目标外包：「你看着办」  
- 标准外包：从不定义好坏，只会点确认  
- 责任外包：出错一律怪模型  
- 假勤奋：整天盯着 Agent 的进度条，比自己做还累  

MadHatter 有一句刺耳的话：委托的真实成本，是你的 agency。  
Agent 未必消灭乏味，它可能只是把乏味变成**监督界面**。

所以主体性要落到机制，而不是口号：

1. 任何任务先写：**目标、边界、禁区、成功标准**  
2. 高风险写操作默认人工确认  
3. 长任务设中途检查点，禁止「跑完再看」  
4. 每周留时间 Training 自己的判断，和学新工具分开  
5. 交付进更大系统前，你要答得出：「我为什么认这个结果？」  
6. 把标准写进 `AGENTS.md` / Skill / 规则——**标准仍属人，只是可复用**  

Levie 还有一层组织洞察：  
那些**已经被外包出去的服务**，最容易被「Agent 版供应商」整包替换。  
对个人也一样——你清单里那些可外包的活，正在加速贬值；  
**真正难被替换的，是谁拥有洞察、优先级和最终签字。**

## 05 明天就能用的工作流

```
人：目标 + 边界 + 成功标准 + 禁区
  → Agent：拆解 / 执行 / 自检 / 出草稿
  → 人：抽检关键路径 + 品味修正 + 承担责任
  → 现实反馈 → 更新你的标准
```

**本周只改一个习惯：**

不要再问「Agent 能不能做」。  
先问——

**这件事的主权，还在不在我手里？**

能验证、可回滚、错误便宜 → 放心扔给它。  
关乎方向、品味、风险与责任 → 留在本人。

Agent 是很强的实习生。  
实习生可以写草稿、跑腿、试错；  
**导演、制片和终审，不能空缺。**

---

## 一页决策卡

- 目标与成功标准是否由人写清？  
- 错误是麻烦，还是灾难？  
- 结果能否快速验收？  
- 写 prompt 是否比自己做更慢？  
- 是否涉及钱 / 生产 / 合规 / 对外承诺？  
- 是否高上下文内核？  
- 有没有人工门与中途检查点？  
- 做完有没有更新你自己的判断？  

规则很简单：

**永远：人签字，Agent 执行。**
