# Research Report：哪些任务适合外包给 Agent，哪些该留给人，以及人主体性的重要性

- **日期**：2026-07-18
- **类型**：主题调研 / 观点综合
- **来源**：X（Twitter）高互动讨论、行业博客与框架文章、OpenAI Agent 实践中文摘要
- **用途**：支撑公众号长文；可二次拆成 X 线程 / 短帖
- **状态**：v1 完整稿（可引用，非实时监控）

---

## 1. 研究问题

1. 在 Agent / Agentic AI 普及后，**哪些任务应委托给 Agent**？
2. **哪些任务必须由人保留**？
3. **人主体性（human agency / subjectivity）**在人机分工中为何不可外包？
4. 有没有可操作的**决策启发式**（工程、产品、运营通用）？

---

## 2. 核心结论（Executive Summary）

| 命题 | 结论 |
|------|------|
| Agent 擅长什么 | 可验证、可模板化、错误成本低、上下文浅的**执行与初稿** |
| 人必须守什么 | **目标、优先级、品味、风险边界、责任签字、现实反馈** |
| 主体性含义 | 不是「亲手敲更多键」，而是**定义好坏并承担后果**的主权 |
| 最大误区 | 把「思考权 / 目标权」连同 Workflow 一起外包 |
| 一句原则 | **外包双手，不外包主权** |

**工作流定式：**

```
人：目标 + 边界 + 成功标准 + 禁区
  → Agent：拆解 / 执行 / 自检 / 出草稿
  → 人：抽检关键路径 + 品味修正 + 承担责任
  → 现实反馈回灌「标准」（AGENTS.md / 规则 / 复盘）
```

## 4. 适合外包给 Agent 的任务

### 4.1 任务类型表

| 类型 | 例子 | 适合原因 |
|------|------|----------|
| 重复生产 | 邮件草稿、会议纪要、周报骨架、社媒初稿、配图生成 | 模板清晰，人只改/批 |
| 浅层阅读 | 文章摘要、资料初筛、竞品列表、日志归类 | 读多写少，可验收 |
| 低风险执行 | 格式转换、脚手架代码、API 样板、图表/前端原型 | 结果可见、易回滚 |
| 结构化调研 | 按清单搜文档、参数对比表 | 范围可框死 |
| 隔离子任务 | 并行修独立模块、独立 code review | 上下文可切开 |

### 4.2 Balaji 工程启发式（浓缩）

AI 更适合：

- frontend over backend  
- reads over writes  
- shallow over core  
- prototypes over production  
- starting vs maintaining  
- error-tolerant over error-intolerant  
- visual output over financial  
- low-context over high-context  

**隐喻**：Agent 是实习生——可尝试外圈，核心高上下文要自报不确定。

### 4.3 OpenAI 视角：何时建 Agent

适合传统确定性规则难处理的流程：

1. **复杂决策**（细微判断、异常、上下文相关）  
2. **难维护的规则集**（规则爆炸、更新成本高）  
3. **强依赖非结构化数据**（自然语言、文档、对话）

否则确定性脚本往往更稳。且必须：**护栏 + 人可接管 + 高风险人工门**。

### 4.4 Levie：工作上移后的人的活

Agent 能跑更长任务后，人的工作变成：

1. 想清楚告诉 Agent 做什么  
2. 给足指令与上下文  
3. 偏航时干预  
4. 验收最终产物  
5. 把输出拼进更大系统  

任一步失败 → 产物无用。**长任务不会消灭计划与验收，反而加重。**

## 5. 应该留给人的任务

| 类型 | 例子 | 原因 |
|------|------|------|
| 定方向 | 做什么/不做、为谁、成功标准 | Agent 优化给定目标，不替你选目标 |
| 价值与品味 | 产品调性、文风、设计好坏、品牌红线 | 主体性本身 |
| 高上下文核心 | 核心后端、资金逻辑、权限/安全、合规 | 错一次贵，暗知识在人 |
| 高风险写操作 | 转账、上线、删库、客户承诺、法律口径 | 需可追责主体 |
| 关系与谈判 | 关键客户、伙伴、冲突调解 | 信任与责任在人 |
| 现实反馈闭环 | 真实用户、市场、亏损复盘、改目标 | Agent 内循环 ≠ 现实 |
| 自我训练 | 难书、高人、痛苦决策复盘 | 更新人的 Base Model |

### 5.1 Long Chen 三层模型（中文高传播框架）

| 层 | 类比 | 建议 |
|----|------|------|
| Workflow | Inference 耗材（回邮、填表、写周报） | 尽量外包/自动化 |
| Skills | Function Calling（某门手艺） | 会贬值，别当唯一护城河 |
| Base Model | 世界观 / 决策框架 / 审美 | **唯一 fortify 的对象** |

口号：**少 Inference，多 Training**。  
警告：系统用 Workflow 填满时间，阻止你微调大脑 → 变成可替换 API。

## 6. 决策框架（可操作）

### 6.1 错误成本 × 可验证性

```
错误便宜 + 结果易验  →  大胆交给 Agent
错误很贵 + 结果难验  →  人主导，Agent 最多参谋
```

### 6.2 委托开销（Rauch）

写清规格 + 验收 + 上下文切换 **>** 自己做 → **不要外包**。  
Agent 再快也挡不住「说明比动手慢」。

### 6.3 三档采购（imFORZA 改写为通用）

| 档位 | 条件 |
|------|------|
| 自己 + AI | 计划清楚、有负责人、能锁时间、错了是麻烦不是灾难 |
| 买搭建与交接 | 团队能跑，卡在选型/接入/权限/测试/培训 |
| 持续外包 | 方向不清、执行总掉、需专才、无人负责结果 |

原则：**只买补缺口的最小帮助**。

### 6.4 同心圆

- **外圈**（UI、图表、样板、调研）：Agent  
- **内核**（业务规则、钱、身份、信任）：人  

### 6.5 Codex / 工程实践（oil-oil）

- 主 Agent：理解需求、控范围、**最终验收**  
- 小改：自己做，不启动子 Agent  
- 仅当需要：隔离上下文 / 并行 / 独立复审 → 再拆  

### 6.6 组织层（Levie）

- 已有外包预算与「买结果」习惯 → 最易换成 agentic 供应商  
- 替换编制是 reorg，难度高  
- 对个人：你的「可外包清单」会被自动化；你的「签字权」才是护城河

## 7. 人主体性：定义、威胁与护栏

### 7.1 工作定义

**人主体性** = 在人机系统中，人仍然拥有：

1. **目标主权**（选问题、定 KPI、砍 scope）  
2. **评价主权**（什么叫好、什么叫过）  
3. **否决与责任**（能停、能改、能背锅）  
4. **现实闭环**（用真实世界反馈更新标准）  
5. **自我更新**（Training 自己的判断，而非只烧 Inference）  

### 7.2 威胁模型

| 威胁 | 表现 | 后果 |
|------|------|------|
| 目标外包 | 「Agent 看着办」无边界 | 勤奋地错 |
| 标准外包 | 从不定义好坏，只点确认 | 品味萎缩 |
| 责任外包 | 出错怪模型 | 组织失能 |
| 反馈断裂 | 只信 Agent 内循环 | 幻觉闭环 |
| 假勤奋 | 全天监督 UI | agency 被掏空（监督成本 > 原工作） |

### 7.3 护栏设计（个人 / 团队）

1. 任何 Agent 任务必须写清：**目标、边界、禁区、成功标准**  
2. **高风险写操作**默认人工门（资金、生产、合规、对外承诺）  
3. 长跑任务强制**中途检查点**，禁止「跑完再说」  
4. 每周固定 **Training 时间**（难材料 + 复盘），与工具学习分开  
5. 产出进更大系统前，人必须能回答：「我为什么认这个结果？」  
6. 把人的标准沉淀进 `AGENTS.md` / Skill / 规则——**标准仍属人，只是可复用**  

### 7.4 哲学与伦理一笔

- 「不要外包人性」：共情、承诺、道德立场无法用流畅文本替代。  
- Agentic AI 让过程不可见时，**专业能力从「会做」滑向「会监督」**；若不主动维护判断，会静默失能。  
- 主体性不是反 AI，而是 **AI 越强，人越要会当导演**。

| 留给人（主体） | 交给 Agent（工具） |
|----------------|-------------------|

| 验收标准与否决 | 实现、重构、批处理 |
| 复盘与改策略 | 数据汇总、对比表 |
| 培养自己的判断 | 练习题、模拟、检索 |

## 9. 可传播话术（内容生产）

**主钩子：**

> Agent 该外包的是双手，不该外包的是主权。  
> 执行可以交给实习生；目标、品味与责任，必须留在本人。

**副钩子：**

- 你不是被 AI 取代，你是被「不会用 AI 的自己」和「只会点确认的自己」夹击。  
- 工作没消失，只是从键入员变成了制片人。  
- 少 Inference，多 Training。  
- 写 prompt 比自己做还慢时，别硬委派。  

**结构建议（公众号）：**

1. 冲突开场（全外包幻觉 vs 主体性）  
2. 适合 Agent 的清单  
3. 必须留给人的清单  
4. 五个决策测试  
5. 主体性护栏与一周实践  
6. 收束金句

## 12. 附录：一页决策卡

```
□ 目标、边界、成功标准是否由人写清？
□ 错误成本：麻烦 / 昂贵 / 不可逆？
□ 结果是否可在 5 分钟内验收？
□ 写 prompt+验收 是否比自做更慢？
□ 是否涉及钱 / 生产 / 合规 / 对外承诺？
□ 是否高上下文核心（暗知识）？
□ 是否安排了人工门与中途检查点？
□ 完成后是否更新了人的标准（Training）？

规则：
- 前 4 项「可 + 便宜 + 可验 + 更快」→ Agent 主导
- 任一「昂贵 / 不可逆 / 核心 / 承诺」→ 人主导
- 永远：人签字，Agent 执行
```
