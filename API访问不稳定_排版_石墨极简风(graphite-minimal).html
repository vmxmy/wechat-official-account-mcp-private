01

WHY TWO ROUTES

为什么提供两个入口

两个域名连接的是同一套 API 服务，差别主要在访问路径。东京线路直接访问服务；上海入口先在上海接入，再转发至东京。

切换时只需修改 API Base URL，模型、密钥和其他调用参数保持不变。

实际体验会受到地区、运营商、DNS 和当前网络拥塞影响，因此不存在对所有人都最快的固定答案。最可靠的方法，是在自己的网络下对两个入口做同一组测试。


02

DEFAULT

默认推荐：东京线路

https://api.gaoxin.net.cn

这条线路适合大多数用户，尤其是访问日本网络质量较好的地区。由于请求路径更直接，通常响应速度更快，建议优先使用。

如果连接、请求和流式输出都稳定，就不需要为了追求几十毫秒的差异频繁切换。


03

BACKUP

备用选择：上海入口

https://api-sh.gaoxin.net.cn

请求会先接入上海，再转发至东京服务。这条线路更适合无法稳定访问东京入口、经常连接超时的国内用户。

稳定

实测请求成功率

约 100～700 毫秒

偶发额外延迟

该入口实测请求成功率稳定，但转发链路仍会受到跨境网络影响，偶尔可能增加约100～700 毫秒延迟。如果上海入口明显变慢，也可以随时切回东京线路。


04

QUICK TEST

用系统命令快速评估

建议在同一设备、同一网络、相近时间测试两个域名，并重复多次。一次结果容易受到瞬时抖动影响，不适合直接下结论。

STEP 01检查 DNS 解析

先确认两个域名都能正常解析。macOS、Linux 与 Windows 均可使用以下命令：

...shell

nslookup api.gaoxin.net.cn

nslookup api-sh.gaoxin.net.cn

如果出现解析超时或找不到域名，先尝试更换 DNS、切换网络或关闭异常代理，再继续测试。

STEP 02用 ping 观察基础连通性

macOS 或 Linux：

...bash

ping -c 5 api.gaoxin.net.cn

ping -c 5 api-sh.gaoxin.net.cn

Windows：

...cmd

ping -n 5 api.gaoxin.net.cn

ping -n 5 api-sh.gaoxin.net.cn

NOTE

ping 使用 ICMP，服务器或网络可能主动屏蔽它。ping 不通不等于 API 不通，结果只能作为基础参考，不能单独决定线路。

STEP 03用 curl 测量真实 HTTPS 链路

相比 ping，curl 更接近真实 API 请求。请分别执行：

...bash / PowerShell

curl -o /dev/null -sS --connect-timeout 5 --max-time 20 -w "http=%{http_code} dns=%{time_namelookup}s connect=%{time_connect}s tls=%{time_appconnect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n" https://api.gaoxin.net.cn

curl -o /dev/null -sS --connect-timeout 5 --max-time 20 -w "http=%{http_code} dns=%{time_namelookup}s connect=%{time_connect}s tls=%{time_appconnect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n" https://api-sh.gaoxin.net.cn

Windows PowerShell 中如遇到 curl 别名问题，请把命令开头改为curl.exe，并把/dev/null改为NUL。

重点看connect、tls、ttfb 和 total。根路径返回 401、404 等 HTTP 状态并不一定代表网络异常；只要能快速完成连接和响应，仍可用于比较链路耗时。

STEP 04用真实流式请求做最终验证

在你的客户端里，把 Base URL 分别切到两个入口，对同一模型发送相同的小请求三至五次。记录是否连接失败、首字出现是否明显变慢，以及输出过程中是否中断。

「真实请求能稳定完成，比单次延迟更有决策价值。」

THE END

按结果切换，不凭感觉

做决定时，请按成功率与流式完整性优先、首字节和总耗时其次的顺序判断。

1

东京入口无超时、流式输出稳定：继续使用东京线路。

2

东京入口频繁连接失败、超时或中断，而上海入口稳定：切换到上海入口。

3

两个入口都稳定：选择多次测试中首字节和总耗时更低的一条。

4

两个入口都不稳定：先切换本地网络、DNS 或代理环境，再重新测试。

需要切换的典型信号：无法建立连接、请求频繁超时、流式输出经常中断，或当前网络无法稳定访问东京节点。

两个域名互为补充，网络环境变化后可以随时重新评估。最终原则很简单：选择自己访问更稳定的线路即可。
